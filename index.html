AWS / AI-Assisted Cloud OperationsCASE STUDY 01

RAG Ops Assistant

An evidence-grounded operations assistant combining retrieval-augmented generation, Amazon Bedrock, LangGraph, MCP and a containerized AWS deployment.

145 local tests passedAWS deployment verifiedTemporary AWS resources were cleaned up after validation.

The engineering problem

Operations documentation is scattered across repositories and runbooks. A useful assistant needs grounded answers and must refuse unsupported or missing facts instead of inventing infrastructure details.

Architecture and implementation

Python and FastAPI integrate a retrieval pipeline, LangGraph orchestration, MCP tools and Amazon Bedrock. Infrastructure is defined with Terraform and AWS ECS Fargate, with image publishing and GitHub Actions OIDC for deployment.

Engineering decisions

Source references, retrieval evaluation, terminology boundaries and refusal cases are explicitly tested. The repository records live query observations and the subsequent AWS resource cleanup. The cloud endpoint is not described as permanently online.

Cloud Reliability / Controlled AutomationCASE STUDY 02

CloudOps Command Center

A cloud operations workspace that turns infrastructure risks into evidence-backed investigations, owner routing and approval-gated simulated remediation.

132 application tests passedApproved execution is simulated, not a claim of live infrastructure remediation.

The engineering problem

Infrastructure alerts alone do not show incident impact, responsible owners or the evidence required to make a controlled remediation decision.

Architecture and implementation

Next.js, TypeScript and PostgreSQL support risk processing, Decision Traces, service ownership, operational findings and workflow records. A shared contract accepts structured findings from PlatformPilot.

Engineering decisions

Authenticated API routes, role permissions and workspace isolation protect operations. Humans must approve simulated remediation; evidence and decision records remain separate from external execution.

PlatformPilot

A Kubernetes operations platform connecting cluster visibility, workload diagnostics, Prometheus monitoring, role-based access and structured operational findings.

Full-Stack SaaS / AI-Assisted OperationsCASE STUDY 04

OpsPilot SaaS

A multi-tenant business operations platform that turns fragmented signals into prioritized recommendations, human-approved actions and trackable workflow records.

304 application tests passed54 PostgreSQL tests passednpm audit: 0 findings

The engineering problem

Business signals across inboxes, notes and customer interactions are easy to miss. Turning them into accountable, authorized action requires reliable workflow and tenant boundaries.

Architecture and implementation

Next.js, TypeScript, Clerk and PostgreSQL underpin workspace authentication, role authorization, signal ingestion, action approvals, execution records and Stripe billing foundations.

Engineering decisions

Business-scoped access, approval attribution and transactional idempotency are tested against PostgreSQL. Public demo workflows remain separate from authenticated tenant data. Financial impact is estimated, not verified revenue recovery.

Microsoft Azure / Secure Application PlatformCASE STUDY 05

PropertyOps AI Agent

An Azure property operations platform demonstrating identity, private networking, infrastructure automation, controlled maintenance workflows and observable application hosting.

The engineering problem

Operational applications need secure access, repeatable infrastructure and observable behaviour, not just business functionality.

Architecture and implementation

FastAPI, PostgreSQL and Azure Container Apps integrate with Microsoft Entra ID, managed identity, Key Vault, Application Insights and Bicep infrastructure.

Engineering decisions

Private endpoints and network boundaries protect supported data services. GitHub OIDC minimizes long-lived deployment credentials, while approval and audit tests validate sensitive workflow boundaries.
